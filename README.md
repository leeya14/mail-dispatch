# Mail Dispatch

메일 예약 발송·취소·실패 후 재시도를 처리하는 Spring Boot 백엔드 프로젝트입니다.

예약 상태와 발송 시도 이력을 조회하고, 로컬 SMTP 수신함에서 결과를 확인할 수 있습니다.

## 실행해 보기

[실행용 ZIP 다운로드 및 실행 안내](https://github.com/leeya14/mail-dispatch/releases/tag/v1.0.0)

### 실행 환경

- Java 17 이상
- Python 3
- 터미널에서 `java`와 `python` 명령을 사용할 수 있도록 PATH 설정

### Windows 실행 방법

1. 위 링크의 **Assets**에서 `mail-dispatch-demo.zip`을 다운로드합니다.
2. 압축을 해제한 뒤 `start-demo.bat`을 실행합니다.
3. 앱이 시작되면 아래 주소에 접속합니다.

| 화면 | 주소 |
|---|---|
| 메일 예약·발송 이력 | http://127.0.0.1:8081 |
| 로컬 테스트 수신함 | http://127.0.0.1:8025 |

실행용 ZIP에는 JAR가 포함되어 있어 별도로 빌드할 필요가 없습니다. GitHub에서 자동 제공하는 `Source code (zip)`과는 다른 파일입니다.

macOS/Linux용 스크립트도 제공하며, `bash start-demo.sh`로 실행합니다. 아래 수동 테스트 결과는 Windows 환경 기준입니다.

### 예약 발송 확인

1. 수신자에 `recipient@example.test`를 입력합니다.
2. 제목과 본문을 입력합니다.
3. 발송 시간을 현재보다 1분 뒤로 설정하고 **메일 예약하기**를 누릅니다.
4. 예약 시간이 지난 뒤 **새로고침**을 눌러 처리 상태를 확인합니다.
5. 로컬 테스트 수신함에서 메일을 확인합니다.

기본 설정은 H2 파일 DB와 로컬 SMTP 서버를 사용합니다. 실제 이메일 주소를 입력하더라도 외부 이메일로 전달하지 않습니다.

### 데이터 보관 및 종료

- 예약 정보와 발송 시도 이력은 `data/`에 저장되며 앱을 다시 실행해도 유지됩니다.
- Python 테스트 수신함의 메일은 SMTP 서버 종료 시 삭제됩니다.
- Windows에서는 앱 실행 창과 별도로 열린 SMTP 서버 창을 모두 종료하세요.
- 재실행할 때는 기존 서버를 먼저 종료하세요.

## 주요 기능

- 수신자·제목·본문·예약 시간 검증 및 예약 등록
- 예약 시각에 따른 SMTP 발송 처리
- 예약 목록·상세·발송 시도 이력 조회
- 상태·예약 시간 조건 검색 및 페이지 조회
- 예약 대기·재시도 대기 요청 취소
- 일시적인 발송 실패에 대한 자동 재시도
- `Idempotency-Key`를 이용한 중복 예약 요청 처리
- 같은 키로 다른 내용을 요청할 경우 HTTP 409 반환

## 실행 확인 결과

Windows 로컬 환경에서 다음 시나리오를 직접 실행하고 API 응답, 발송 상태, 시도 이력 및 로컬 수신 결과를 확인했습니다.

| 시나리오 | 확인 결과 |
|---|---|
| 정상 예약 발송 | 발송 시도 1회 후 SMTP 접수 성공 및 로컬 수신 확인 |
| 예약 취소 | 취소 상태로 변경되고 발송 시도 0회 유지 |
| 일시 오류 후 재시도 | 첫 시도 실패 후 30초 뒤 두 번째 시도 성공 및 로컬 수신 확인 |
| 재시도 한도 | 30초·60초 간격으로 재시도하고 총 3회 실패 후 최종 실패 상태 유지 |
| 동일 요청 반복 | 최초 HTTP 201, 재요청 HTTP 200 및 동일한 예약 ID 반환 |
| 동일 키로 내용 변경 | HTTP 409 반환 |
| 실행용 ZIP 검증 | GitHub Releases에서 다시 다운로드하여 실행 및 예약 발송 확인 |

동일 요청 반복 테스트에서는 예약 목록에도 하나의 예약만 표시되는지 확인했습니다.

## 발송 상태

| 상태 | 의미 | 취소 처리 |
|---|---|---|
| `PENDING` | 예약 시각 대기 | 가능 |
| `PROCESSING` | 작업 선점 후 SMTP 처리 중 | 불가 |
| `SMTP_ACCEPTED` | SMTP 서버가 메일 접수 | 불가 |
| `RETRY_WAIT` | 일시 오류 후 다음 시도 대기 | 가능 |
| `FAILED` | 영구 오류 또는 시도 횟수 소진 | 불가 |
| `CANCELLED` | 사용자 취소 | 기존 취소 결과 반환 |

화면의 **메일 서버 전달 완료**는 `SMTP_ACCEPTED`에 해당합니다. SMTP 서버의 접수 성공을 의미하며, 최종 수신자의 받은편지함 도착을 보장하지 않습니다.

## 설계 포인트

### 중복 요청 처리

`Idempotency-Key`의 SHA-256 해시를 저장하고 DB UNIQUE 제약으로 동시 중복 요청을 처리합니다.

요청 내용은 각 문자열의 길이와 내용을 결합한 fingerprint로 비교합니다.

- 같은 키·같은 내용: 기존 예약 반환
- 같은 키·다른 내용: HTTP 409 반환
- 키의 대소문자 구분

### 발송 작업 선점과 취소

트랜잭션 안에서 `SELECT FOR UPDATE`로 예약 행을 잠근 뒤 발송 작업을 선점합니다.

발송 처리가 시작되어 `PROCESSING`으로 전환된 요청은 취소할 수 없습니다. 예약 대기 또는 재시도 대기 상태에서만 취소를 허용합니다.

### SMTP 호출과 DB 트랜잭션 분리

발송 시도를 기록한 뒤 트랜잭션 밖에서 SMTP를 호출하고, 통신이 끝나면 결과를 저장합니다.

SMTP 응답을 기다리는 동안 DB 잠금을 유지하지 않도록 구성했습니다.

### 오류 분류와 재시도

일시적인 SMTP 오류는 최초 시도를 포함해 최대 총 3회 시도합니다. 기본 재시도 대기 시간은 30초, 60초입니다.

인증 오류·파싱 오류·SMTP 5xx는 재시도 없이 실패 처리합니다. 전송 결과가 불확실한 연결 오류는 제한적으로 재시도하므로 중복 전달 가능성이 있습니다.

### 시간 처리

API는 UTC 또는 오프셋이 포함된 ISO 8601 형식의 시간을 받습니다. DB는 UTC 기준으로 저장하고, 화면은 사용자 기기 시간으로 표시합니다.

예약 시간 조회 범위는 `from` 포함, `to` 미포함입니다.

## 소스 빌드 및 자동 검증

소스에서 빌드하려면 JDK 17 이상과 Maven이 필요합니다. `pom.xml`이 있는 프로젝트 루트에서 실행합니다.

```bash
mvn clean verify
```

빌드된 JAR와 로컬 SMTP 서버를 사용하는 연동 검증은 다음 명령으로 실행합니다.

```bash
python3 tools/verify_e2e.py
```

Windows에서 Python 명령이 `python`으로 등록되어 있다면 다음과 같이 실행합니다.

```powershell
python tools/verify_e2e.py
```

연동 검증 스크립트는 임시 포트에서 앱과 SMTP 서버를 실행합니다. 첫 SMTP 시도에 451 오류를 응답하도록 설정한 뒤 재시도, 로컬 메일 수신, 중복 요청 및 취소를 검증합니다.

외부 이메일 발송은 발생하지 않습니다. 결과는 `docs/e2e-result.json`에 저장됩니다.

자동 테스트의 결과와 검증 범위는 [테스트 보고서](docs/TEST_REPORT.md)를 참고하세요.

## 적용 범위와 한계

- 단일 애플리케이션 인스턴스를 기준으로 한 로컬 데모이며, 기본 서버 주소는 `127.0.0.1`입니다.
- 인증·권한·사용자별 데이터 분리·발송량 제한은 구현하지 않았습니다.
- SMTP 접수와 DB 결과 저장은 하나의 원자적 트랜잭션이 아닙니다. 전송 결과가 불확실한 상황에서 재시도하면 중복 전달될 수 있으며, 정확히 한 번의 발송을 보장하지 않습니다.
- `PROCESSING` 상태에서 서버가 종료된 요청은 자동 재발송하지 않습니다. 시도 이력과 수신 여부를 확인한 뒤 수동 조치해야 합니다.
- 다중 서버·대량 발송·MySQL 잠금 동작·성능은 별도 검증이 필요합니다.
- DB 마이그레이션 도구는 적용하지 않았습니다. `schema.sql`은 최초 테이블 생성용이며 기존 스키마 변경을 자동 반영하지 않습니다.

## 개발 과정

생성형 AI(Codex)를 개발 보조 도구로 활용했습니다. 직접 로컬 환경에서 주요 기능과 예외 시나리오를 실행하여 응답·상태·이력을 확인하고, 배포한 실행용 ZIP의 동작을 검증했습니다.
